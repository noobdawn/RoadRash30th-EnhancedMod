## 翻滚中闪出奔跑画面的初次修复（2026-11-17）

以下记录首次随长跑安装的实现；当前作用范围和设置入口以上节为准。

原版人物受撞函数 RVA `0x13F80` 在奔跑者被高速对象撞倒时，把车辆状态改为 `1`（倒地），立即播放 `0x22` 受撞动作，却在 `0x14124` 将 `0x26`（奔跑）排为下一动作。倒地动画控制器 `0x19920` 遇到当前动作 `0x22` 时只推进动画，不重选翻滚；因此动画结束后会短暂切到奔跑，之后才按滑行速度重新选择翻滚。这条错误衔接存在于原版受撞路径，长跑持续处于步行状态时会更常进入此路径；不依赖屏幕内外切换。

修复在长跑范围内将该处的后续动作改为原版同一碰撞路径已经使用的 `0x1C` 翻滚。保留受撞动作、碰撞位移、冲量与速度，以及原版滑行结束后的起身 `0x24` → 站立 `0x25` → 奔跑 `0x26` 流程。普通模式、未选中的玩家/AI 仍执行原指令；恢复上车策略独立。补丁位于既有代码区 `+0x3800`，全部入口签名通过后才发布跳转。

后台回归实际执行游戏的受撞函数、立即/排队动画函数、动画时钟、倒地决策和起身追车代码；动画资源使用带结束标记的两帧测试数据，声音及碰撞物理积分使用替身。旧实现复现为倒地状态下 `22 → 26 → 26 → 1E`；修复后为 `22 → 1C → 1E`。覆盖四档输入速度、玩家/AI、三个长跑范围、四种恢复策略、二次受撞、原版起身后恢复跑步和签名拒绝安装，新增 212 项比赛检查，比赛专项 780 项、整体验证 1269 项通过。

整体验证同时发现既有单选手走位测试受地址随机化影响：短时间随机选线未必覆盖所有车道。只调整该测试的身份种子与观察窗口，游戏走位实现没有修改。证据、旧启动器/源码/配置及首轮失败日志保存在 `artifacts/run-fall-animation-20261117/`。两个启动器已更新，现有配置保留；未启动真实游戏，完整画面仍待实机确认。真实游戏测试前先告知用户。

## 重新加载后人物歪斜（2026-11-17）

用户反馈部分长跑选手从屏幕外进入画面后向左歪斜，并确认是显示朝向/姿态异常，跑动路线基本正常。排查对应详细模拟的重新加载路径，未改动跑线、配速或交通驾驶规则。

原因：RVA `0x16041` 的长跑恢复钩子临时设为骑行状态，调用原版 `0x17510` 同步人物位置及道路上下文。该函数同时复制摩托车 `+0x58/+0x5C/+0x60` 的俯仰、朝向和侧倾；隐藏摩托车的旧倾角因此进入人物。人物实际移动由 `+0x128` 控制，绘制经 `0x4A0B0` 将角度复制至 `+0x64/+0x68/+0x6C`，再由 `0x28140` 读取朝向及侧倾。两套角度可不一致，形成路线正常但身体偏斜的表现。

修复在长跑重新加载、原位置同步之后，清零人物俯仰和侧倾，显示朝向采用人物原有的实际运动方向 `+0x128`，并立即刷新渲染坐标/角度。只作用于原本保留长跑状态的范围与恢复策略；正常骑行仍按原版复制车体姿态。人物坐标、实际方向、引导车角度、配速和换线决策保持原有逻辑。

新增回归先用旧实现失败复现，再验证修复：旧版记录实际方向 `-1048576`、显示朝向 `-4194304`，人物侧倾与原版绘制侧倾均为 `-2621440`。修复覆盖左右/零侧倾、左右/正前运动方向、玩家/AI、重复渲染刷新及全部范围/恢复策略，直接执行原版角度函数。97 项新增检查通过，整体后台回归 1057 项通过，比赛专项 568 项。旧启动器、源码、配置与前后验证日志位于 `artifacts/run-reentry-pose-20261117/`。未启动实际游戏，仍需实机确认用户场景；真实游戏测试前先告知用户。

## 骑行选线与交通驾驶（2026-11-17）

本节覆盖下方“稳定跑线、提前绕车让速”的上一阶段设计。用户要求长跑 AI 保持骑行的选线特点，主动穿行车流，保留被撞机会；同时增加同向、对向交通车独立调速与“疯狂司机”。本次仍不做提前看弯道、入弯限速、攻击或追击选手。

长跑横向目标采用原版 RVA `0x1ABC0` 的车道计算：道路横向原点 `+0xCC`、250 单位车道间距、选手档案 `+0x18C` 的内/中/外车道偏好及 `+0x190` 的车道内偏移。取当前路段，不读取前方弯道；每个 AI 独立定期重选车道，部分决策回到原偏好，其他决策可选择两侧车道。低/中/高的决策间隔约为 13–16 / 10–13 / 7–10 秒，配合 ±8/16/24 单位小幅变化，已有引导目标限速平移继续生效。人物仍通过移动摩托车位置引导，不直接传送人物。

交通车只进入约 6 个模拟步、48–192 纵向单位的近距离反应窗口，闪避权重降低，且不触发自动让速。远处车辆不会把整条跑线提前清空，近处也不保证避开。静态障碍与简单人群空间避让继续保留；人物与交通的真实碰撞仍交给原游戏。原版偏好只作为部分决策，独立随机换线覆盖道路两侧，避免所有人聚向同一边。

高级 → 赛道与规模 → 交通车辆驾驶：

| 设置 | 默认与行为 |
| --- | --- |
| 同向车辆速度倍率 | 1；独立缩放同向普通交通车的目标速度与加速度 |
| 对向车辆速度倍率 | 1；独立缩放对向普通交通车的目标速度与加速度 |
| 疯狂司机 | 关闭；每车约 1.6–4 秒重新决策，可选双侧车道，约 25% 的目标在铺装边界外 96 单位 |

速度可输入小数，0 表示停止，没有 8 倍或其他人为玩法上限；UI 支持非负 decimal 数值。运行时仅在原版有符号 32 位速度字段表示不下时饱和，并保护加速度乘加不变成负数；极端倍率的整车物理效果未作保证。很小的正倍率仍可从静止加速。数量预设不覆盖驾驶参数，新设置同样适用于正常骑行模式，旧配置默认 1/1/关闭。

交通方向依据生成器 RVA `0x6B1AD`、车辆 `+0x1CC` 及方向表验证：0 为同向，2 为对向；1/3 为横穿道路的车辆，保留原状。补丁只处理对象类型 16 的普通交通车，不影响选手摩托车、玩家汽车外观。RVA `0x6A375` 在原版已生成目标速度、方向之后接入；疯狂司机修改 `+0x1DC/+0x1E0` 方向向量，经原版 `0x62980` 转向/加速，随后仍由原生移动、碰撞和回收逻辑处理。车辆坐标不被直接改写；路肩/人行道目标不保证穿过地图实体障碍。

源文件 `LongRunAi.c` 与 `TrafficDrive.c` 均生成无重定位、无导入的 x86 代码。分别运行 `scripts/build-ai.py --tool-dir <工具目录>` 与同命令加 `--module traffic` 更新生成文件；`scripts/build.ps1` 编译启动器。配置升级为 8，新增 `sameTrafficSpeed`、`oppositeTrafficSpeed`、`crazyDrivers`，现有用户配置不覆盖。

后台验证涵盖原版交通调用点签名与转向/加速函数、双向独立倍率、零速/小数/超大值、车道及路肩目标、不直接改坐标、原骑行档案参与跑线、交通碰撞机会、配置保存和旧配置迁移。此前 64 组“保证绕过交通车”的模型断言已按新需求改为“持续前进且存在真实轨迹重叠机会”，不再把完全不撞车作为通过条件。模型不包含完整游戏物理，不能替代真实赛道观感测试。

本轮代码、旧启动器和设置快照及后台验证结果保存在 `artifacts/traffic-driving-20261117/`。未启动实际游戏；实机测试前必须提前告知正在工作的用户。

最终验证：完整后台回归 958 项通过，随后 UI 扩展验证由 46 项增至 48 项并全部通过，当前共 960 项检查；其中跑线 96 项、交通驾驶 47 项。已检查离屏交通设置卡片，两个安装目录启动器更新为同一构建，原用户设置文件哈希与备份一致。测试日志分别为 `test-results.txt`、`ui-results.txt`。

## 使用

一键设置 → 比赛设置：正常、车辆、泥头车、长跑。前三项保留原车辆玩法，切换时关闭长跑并恢复原版超时上车。四项均默认开启玩家车辆无限耐久。

长跑预设在倒计时结束后的第一次模拟更新令选手翻车，起身后持续把各自车辆移到前方，默认作用于所有人、领先 96 个游戏路程单位、关闭超时恢复上车，并开启“倒地后隐藏车辆”和中等强度“AI 长跑变化”。AI 通过隐藏车辆的引导位置沿各自跑线奔跑；玩家仍可用方向键控制。隐藏开关本身只影响绘制；长跑范围内正在跑步的车辆另行排除碰撞配对，避免引导点撞人。人物和交通的碰撞保留，恢复骑车后车辆恢复原版碰撞。

高级 → 赛道与规模 → 长跑与恢复上车：

| 设置 | 取值 |
| --- | --- |
| 长跑范围 | 仅 AI / 仅玩家 / 所有人（玩家与 AI） |
| 车辆领先距离 | 32–192 个游戏路程单位，默认 96；并非米 |
| 超时恢复上车 | 所有人（原版）/ 仅 AI / 仅玩家 / 关闭 |

超时恢复上车独立于长跑开关。关闭只禁止超时恢复；跑到车旁仍可按原版规则上车。长跑通过持续保持领先距离让目标选手追不到车。允许超时恢复的人仍可按原版逻辑恢复骑车。长跑且禁用恢复的选手，在屏幕外模拟时也使用人物跑速，回到加载区域继续跑步。

玩家与 AI 的跑速在高级 → 玩家与战斗中分别设置，已取消 8 倍限制。同组可独立开关“倒地后隐藏车辆”。人物防撞倒、车辆外观、赛道、人数、交通均可继续微调。手动更改长跑范围、领先距离、隐藏车辆或恢复策略后，比赛预设显示“自定义”。设置在下一次从启动器启动游戏时生效。

配置版本 5 新增 `longRun=0`、`longRunScope=2`、`remountPolicy=0`、`chaseDistance=96`。范围 0/1/2 对应 AI/玩家/所有人；恢复 0/1/2/3 对应所有人/AI/玩家/关闭。旧配置默认不开长跑并保留原版恢复行为。

版本 6 新增 `hideFallenVehicles`，长跑预设为 1，其他比赛预设为 0。旧配置已经开启长跑且没有此字段时默认启用隐藏；显式保存为 0 后不会在重启时强制打开。该轮后台回归 563 项 PASS；验证详见[人物设置说明](character-features.md)。

## 检查结果

### 2026-11-17 道路选线重做的依据与约定

上一版完成独立配速、冲刺恢复、有限追赶和横向随机目标，619 项后台检查通过；用户实机反馈选手集体向道路右侧移动，未形成公路上的人群。原测试使用人工设定的对称边界，只验证能转向与速度变化，未验证真实道路字段和人群横向分布。当前代码将路段 `+0x14C/+0x158` 作为通用道路边界的假设需要撤销。这些字段还用于特定路段的地形计算，不能直接代表所有道路可跑范围；偏右的全部成因尚未实机确认。

已查明当前游戏程序的骑行模拟：加载范围内记录实际前进路程和时间；卸载时以平均速度为基础，玩家前方乘 95%、后方乘 105%（RVA `0x16446` 起）。远处按速度乘模拟时间更新路程和路段（`0x15980`），另有定期调整玩家前后选手虚拟速度的逻辑（`0x17300`）。加载范围内先生成纵向目标、横向目标和目标速度，再执行转向、加速、制动（`0x196B0`）；道路选线在 `0x1ABC0/0x1ACE0`，障碍避让在 `0x182B0`，弯道限速在 `0x18C70`。证据保存在 `artifacts/ai-driving-analysis/`。屏幕边缘与详细模拟的加载边界并不等同。

本次确定的实现范围：继续移动隐藏摩托车，作为人物追逐的引导点；保留人物移动、碰撞、终点和玩家手动控制。按当前道路可跑范围为每个 AI 分配相对稳定的跑线，配合小幅平滑变化；遇到交通、障碍或过近跑者时局部绕行，拥堵时适度让速，畅通后回归原跑线。不得使所有人追逐同一公路中心或玩家横向位置。不做提前看弯道、入弯限速，也不做攻击、追击或针对选手的互动；简单空间避让保留。速度节奏与有限追赶继续在加载区内外共用，卸载不重置选手偏好。

验收需覆盖真实道路字段生成与边界含义、左右/偏置/窄路、稳定且分散的跑线、双侧绕行、并排与拥堵、目标平滑、加载转换、原版追车入口及大人数的计算量。后台验证不等同完整赛道实测；启动真实游戏前必须提前告知用户。

### 道路选线实现与验证

已由原版道路生成片段 RVA `0x74D5D` 和路面分类函数 `0x4E180` 交叉确认：铺装路面边界为路段 `+0xE0/+0xE4`，由横向原点减左侧宽度、加右侧宽度计算。新走位使用这组边界，扣除人物半宽和安全余量。每个 AI 的偏好位置按身份和比赛种子确定，分布在可跑范围内，配合低频小幅变化；不再向玩家横向位置聚拢。

引导目标保存在启动器分配的私有 1 MiB 状态表中，不占用游戏对象字段。目标每个模拟步按速度及走位档位限速平移，每 6 个模拟步重算局部路线；同一时刻的多次钩子调用不重复推进。离开加载范围后只计算配速，回来从实际人物位置平滑接续；比赛时钟回退时清除旧转向进度，身份偏好继续确定跑线。

局部避让沿原版按纵向位置排序的对象链双向各检查至多 48 个节点，过滤不同分支、未加载对象和引导摩托车。按实体半宽、纵向间距与前进速度选择通行位置；同速前进者不会被视为静止障碍而集体刹车。障碍观察距离随当前配速（包括冲刺）调整；只观察前方对象，不读取弯道曲率或设置入弯限速。到达空跑线前会按剩余横移时间控制接近速度，避免仅目标安全而实际轨迹来不及让开。局部拥堵额外乘以 15%–100% 的速度系数，畅通后回归配速节奏。

摩托车前移时先用人物目标横坐标解析岔路，再补回原版上车位置的 `6000` 定点偏移；这项偏移不会再改变岔路选择。长跑车辆状态 2 的碰撞配对在 RVA `0x49610` 过滤，作用范围与长跑范围一致，不修改碰撞标记、不禁用人物碰撞；状态回到骑车、倒地滑行或上车动画后使用原碰撞流程。

测试执行了原版道路边界计算、路面分类、两条人物追车入口、岔路和屏幕外推进；另有 512 人横向分布及密集队伍模型、16 组分布下的 1 倍/5.5 倍/10 倍/冲刺绕车轨迹、目标平滑、窄路、不同分支、同速跟随、拥堵恢复和引导车辆碰撞过滤。模型使用简化追逐运动，未覆盖完整物理、连续复杂路障或所有真实赛道；不能保证极高倍率下完全避开碰撞。测试输出及旧启动器/配置备份位于 `artifacts/run-lanes-20261117/`。

### AI 长跑变化（2026-11-17）

高级 → AI 设置 → AI 长跑变化，提供总开关及四个“关闭 / 低 / 中 / 高”选项。只影响参加长跑的 AI；仅玩家长跑时不安装变化逻辑。普通车辆预设关闭总开关，长跑预设把四项设为中。缺失新字段的旧长跑配置默认启用，手动关闭和四项独立选择会保存。

| 选项 | 低 / 中 / 高 |
| --- | --- |
| 节奏变化 | 基础跑速 ±7.5% / ±15% / ±22.5%，每个 AI 独立平滑过渡 |
| 冲刺频率 | 周期 28–36 / 20–28 / 12–20 秒；冲刺约 2–4 秒，之后约 3–5 秒恢复，其余时间冷却 |
| 追赶强度 | 最多 ±7.5% / ±15% / ±22.5%；落后适度提速，领先适度减速，恢复期作用减半 |
| 横向走位 | 稳定跑线上的变化幅度 ±8 / ±16 / ±24 个横向单位；档位同时影响目标移动速度，开启后包含道路约束和局部避让 |

冲刺速度增加基础跑速的 20–35%，恢复阶段减少 10–20%，起落使用平滑曲线。配速节奏合计限制在基础跑速的 65–145%，加载区的避让减速另行叠加；超大速度会饱和到游戏速度字段的表示上限。距离调整存在 128 个游戏纵向单位的缓冲，逐渐增加到上限，避免刚超车就急变。单位不是米。上述秒数按原版每秒 60 个模拟步折算；节奏由比赛模拟时钟驱动，不读取显示帧率或系统时间。

各选手使用自身身份和本次启动的种子，不能因相同内存分配间距而共享节奏。加载区内两条人物跑速路径与屏幕外虚拟进度调用同一个函数；同一模拟时刻重复调用不会推进或重置节奏。横向走位通过移动前方车辆目标，由原版追车代码转向；不直接传送人物，也不修改玩家输入。未加载路段时跳过道路读取，重新加载后恢复目标走位。允许 AI 自动上车时，上车后仍恢复原车辆玩法。

配置版本 7 新增 `aiRunVariation`、`aiRunRhythm`、`aiRunSprint`、`aiRunChase`、`aiRunWeave`。四个强度值为 0–3，缺省 2；总开关缺省跟随旧配置的 `longRun`。

实现：`src/LongRunAi.c` 是无外部依赖的 x86 计算函数，只读游戏对象，写入启动器私有的转向状态表。生成的 `LauncherAiNative.cs` 随源码保存，常规启动器构建仍只需要 .NET Framework。修改 C 后用 `python scripts/build-ai.py --tool-dir <GCC/binutils目录>` 重新生成；脚本拒绝外部引用、重定位与独立数据段，测试校验源码哈希。`LauncherAi.cs` 管理界面、运行时函数、参数区和私有状态表。配置字段仍兼容版本 7，无需重设原有选项；横向走位关闭时使用原先的直线追车方式。

验证涵盖实际 x86 函数的节奏独立性、速度范围、平滑性、冲刺恢复、频率档位、暂停与重复调用、进出加载区、极大倍率、原版追车方向、两条加载区跑速入口及屏幕外进度。后台模型中玩家 10 倍、AI 基础 9.5 倍可交替超越；模型不包含真实交通、碰撞或完整赛道，不能代替实机手感验收。结果见 `artifacts/long-run-ai-20261117/test-results.txt`。

原版起身追车代码按人车纵向和横向距离决定方向，没有远距离停止追赶的条件。原版上车条件包括近距离接近车辆，以及等待计数超过 1200；另外，卸载路段也会强制恢复骑车。因此只把车辆移到终点并不足以可靠实现长跑。

当前实现使用选手正在加载的路段作为车辆移动起点，调用原版路段移动函数处理相邻路段和岔路，刷新历史与渲染坐标。终点判定仍由原版人物位置决定，车辆先到终点不会结束人物的比赛。人物完成比赛后停止前移车辆。

`src/LauncherRace.cs` 按玩法和上车设置安装比赛规则。`src/LauncherFixes.cs` 为所有玩法安装离车人物的路段检查。两者均校验游戏指令后写入进程内存，退出游戏即失效。

| RVA | 用途 |
| --- | --- |
| 0x66307 | 保留原输入轮询，在比赛计时第 1 次更新触发开局翻车；每场比赛自动重置 |
| 0x17CA7 / 0x19F4E | 两条下车逻辑：持续前移车辆及控制超时上车 |
| 0x16417 | 卸载路段时，为禁止恢复的长跑选手保留跑步状态，并关闭人物碰撞标记 |
| 0x15BE0 | 屏幕外使用玩家/AI 各自的跑速，不套用骑车追赶倍率 |
| 0x16041 | 重新加载后同步人物路段和姿态，恢复跑步动画 |
| 0x16242 | 所有玩法在离车人物缺少路段时跳过本次地面计算，避免空指针和重复扣减剩余路程 |
| 0x49610 | 跳过长跑范围内状态 2 引导车辆的碰撞配对，保留人物及恢复骑车后的碰撞 |

## 2026-11-17 开局闪退修复

Windows 应用程序错误记录：2026-11-17 00:13:19，`RoadRash95.exe`，异常 `0xC0000005`，RVA `0x495F9`。该指令为碰撞遍历中的 `mov al, [eax+0x36]`，其中 EAX 来自对象的路段指针 `+0x2C`。

长跑卸载钩子跳过了原版恢复上车函数，以保留跑步状态，但同时遗漏了该函数 RVA `0x12CB9` 对人物 `+0xC0` 低两位的清理。后续原版卸载代码清空人车的路段指针，人物却仍带着碰撞标记，导致碰撞遍历访问空路段。修复在保留状态 2 的分支补回 `rider->flags &= 0xFC`；重新加载时仍先同步路段，再恢复碰撞标记。

新增 96 项检查。旧实现会在“完整卸载后人物必须关闭碰撞标记”断言失败；修复后执行原版完整卸载及碰撞遍历，覆盖人物在链表两种位置、全部范围与恢复策略，以及重新加载时恢复碰撞。旧测试只执行卸载钩子，在 `0x1641C` 提前返回，没有覆盖随后清空路段及碰撞的组合。

证据保存在 `artifacts/long-run-crash-20261117/regression-before.txt` 和 `regression-after.txt`，同目录保留原启动器及配置备份。
