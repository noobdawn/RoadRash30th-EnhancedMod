# Road Rash 击倒仪表的精灵合成

0.5.0 使用带源色键的 DirectDraw 精灵，在液晶表右侧绘制单行连击火焰。下文保留早期黑白矩形的诊断和各版修复证据。当前效果与可复现的步骤见「连杀火焰」和「离线复核」。

早期测试的 2017×572 截图中，异常矩形从 x=149 到 1885、y=132 到 473，宽 1737、高 342。当时的启动器提交一块 386×76 的 32 位 DIB 蒙版，两次 `StretchDIBits` 先做 `SRCAND`，再做 `SRCPAINT`。HD 日志记录的缩放倍率是 4.5，与矩形的两边吻合。

## 从资源到屏幕

下表的地址都是各自模块的 RVA。游戏指本机 `RoadRash95.exe`，HD 指 `RoadRashHD.dll`。

| 阶段 | 程序位置 | 实际行为 |
| --- | --- | --- |
| 读仪表 | 游戏 `0x68500`、`0x68530` → `0x68780` | `.BOB` 中一个字节表示一个调色板编号。大、小仪表分别为 190×64 和 95×32。摩托仪表按 640 或 320 字节一行，实际高度取决于读到的字节数。加载器逐行复制，每行在目标表面上前进 `lPitch` 个字节。 |
| 设置透明色 | 游戏 `0x5F7F0`、`0x5FA6E` | 设备创建 8 位索引色的 DirectDraw 系统内存表面。仪表和摩托驾驶舱两块素材表面都设置 `DDCKEY_SRCBLT`，上下界都是索引 0。在本机原版调色板中，0 是蓝色，1 才是黑色。透明由索引决定。 |
| 画驾驶舱 | 游戏 `0x69460` | 原版用 `BltFast` 的 `DDBLTFAST_WAIT | DDBLTFAST_SRCCOLORKEY`（`0x11`）叠到比赛后缓冲。源像素为 0 时，DirectDraw 保留下方字节。驾驶舱底边对齐 640×480 或 320×240 的逻辑视口。 |
| 画 HUD 和提交 | 游戏 `0x5D7BB`、`0x5D7E1`、`0x67B80` | 先画驾驶舱、指示器，再对同一表面取得 DC 画原版文字。新版计数器在取 DC 之前叠加。提交时游戏读取当帧调色板、锁定整个后缓冲，将像素指针和实际行距传给显示例程。 |
| HD 合成 | HD `0x5351`、`0x3DF0`、`0x8040` | HD 在画 HUD 前把采样值同时写入游戏缓冲和自己的 640×480 基准。输出时先按当帧调色板转换高清场景，再逐行比较两个缓冲的索引。只有改变的索引才按逻辑像素边界覆盖高清画面。 |

HD 在 `0x4AE1` 检查游戏处于高细节模式且逻辑表面为 640×480。HD 可以另外使用 428×240 的场景相机，计数器仍按 HUD 视口居中。4K 模式下，HD 在 `0x82C1` 计算出的 HUD 横边界为 [480, 3360)，纵边界为 [0, 2160)。

## 修复与对照

新版在自己的内存中排版五位液晶和连杀字。转换为精灵时，覆盖率低于一半的像素写为透明索引 0，其余颜色映射到 `DATA/PALETTE.RAW` 的 1–255。然后按锁定表面的行距上传，一次色键 `BltFast` 画到原版仪表所用的后缓冲。衰减进度、抖动和倾斜都在源精灵中完成。

| 离线对照 | 本机结果 |
| --- | --- |
| 两次 GDI 运算，输入整块全透明，对真实 8 位 DirectDraw DC 绘制 | 29,336 个目标索引中 28,715 个被改写，其中 16,831 个变成黑或白。 |
| 新版 x10，真实 640×480 DirectDraw 表面 | 9,490 个有色精灵像素按源编号绘制，297,710 个透明或位于精灵外的目标索引全部保留。另覆盖 320×240、低细节使用 640×480 背板、车表加载行距和游戏调色板渐变。 |
| 原版素材 | 重放游戏逐行拷贝例程，核对两个仪表文件及 RAT、SPORT、SUPER 的六套高低细节驾驶舱。用真正的 DirectDraw 绘制六套驾驶舱，再叠加新版 x10，原车仪表区域逐字节一致。 |
| 3840×2160，重放 HD 原始 x86 合成例程 | 全透明旧蒙版与单画驾驶舱相比改写 580,540 个输出像素。换为新版后，全部 8,294,400 个输出像素与独立按索引推算的结果一致，计数器和连杀字有效像素以外的误改数为 0。1280×720 对照也通过。 |

高清测试场景在同一个逻辑像素内放入不同的细节颜色，底部叠加原版 SPORT 驾驶舱。这样可以发现整块复制低分辨率背景导致的画面退化。测试覆盖内存中的 DirectDraw 合成和已安装 HD 模块的显示算法，实际比赛呈现仍待游玩验证。

## 从内嵌原稿追到精灵像素

从常用启动器和图集验证版分别提取名为 `KnockdownHud.png` 的资源，并在独立的 .NET 10 宿主中调用各自的 `LoadKnockdownAtlas`。两张图都是 320×112。独立解码器读出的 RGBA 转为 Windows 的 BGRA 后，逐字节匹配各自启动器的结果，包含完全透明像素的颜色分量。两份原稿本身不同。

| 保持相同的条件 | 实验结果 |
| --- | --- |
| 比较两张原稿相同的液晶玻璃区域，x=12–98，y=14–42 | 常用启动器的 2,523 个像素里有 301 个 Alpha 为零，验证版的 2,523 个像素全部不透明。 |
| 同一份旧绘制代码、相同的 `000`，只换原稿 | 用旧图时，数字盖住了 106 个孔，剩余 195 个传到了 GDI 蒙版。换为验证版图集，这块玻璃上的孔全部消失。 |
| 同一块 8 位 DirectDraw 背景，向 GDI 提交上一步的两套实际输入 | 旧图有 4,087 个应保留背景的位置，4,072 个被改写。只换图后，3,892 个应保留背景的位置中仍有 3,885 个被改写。玻璃里的孔和整块矩形变色各有独立的复现条件。 |
| 将原版 256 个调色板编号转成 RGBA，再由验证版的正常绘制入口生成精灵 | 先前的 5 位 RGB 查表把 7 个原版颜色映射成其他颜色，其中包括将深灰索引 254 映射成黑色 1。本次改为按完整 RGB 选色，并缓存重复颜色。全部 256 个编号和原版仪表的 128×48 区域逐字节往返一致。 |

以验证版显示 `00000` 为例，两次绘制的背景编号分别为 17 和 201。下表列出 DirectDraw 锁定的实际源表面及两个目标表面的读数。

| 取样 | 原稿坐标 | PNG 的 RGBA | 解码的 BGRA 字节 | 精灵索引 | 两个背景上的最终索引 |
| --- | --- | --- | --- | --- | --- |
| 表体外侧 | (0,0) | 0, 0, 0, 0 | 00 00 00 00 | 0 | 17 / 201 |
| 表壳暗边 | (5,24) | 28, 27, 37, 255 | 25 1B 1C FF | 228 | 228 / 228 |
| 液晶玻璃 | (12,24) | 9, 39, 23, 255 | 17 27 09 FF | 130 | 130 / 130 |
| 第一位 0 的顶段 | (8,88)，绘于 (22,17) | 124, 255, 120, 255 | 78 FF 7C FF | 93 | 93 / 93 |

还从内嵌 PNG 独立计算了五位 `12345` 和半程 `×10` 连杀的排版、覆盖率及精灵索引。高、低两档的每个有效源像素及两个背景上的整帧均与实际读数一致。图集验证版的运行日志带有“全精度调色板匹配”字样。

## 连杀火焰

单行连杀标语位于顶部液晶表右侧。字形、火焰和抖动共用仪表的 50 像素高条带，低精度为 25 像素。整张标语最多占绘制区宽度的 22.5%，在 428×240 的逻辑画面中会进一步缩小，整场都给道路留出仪表下方的空间。两连点火，五连和十连提高击倒瞬间的火势。新击倒后的半秒有轻微抖动，650 毫秒后恢复常态火焰，字面继续显示剩余时间。

正式版使用游戏目录中的 `暴力摩托增强启动器.exe`。在 640×480 离屏画面中，×23 连击后 600 毫秒，旧版标语与火焰占 412×164 像素，新版占 105×35 像素，实际改写的像素从 37,952 降至 2,150。连续读取 64 帧，火尖和文字均处于仪表高度内。本机开发归档中保留了 `repository/artifacts/knockdown/meter-strip/comparison.png` 和同目录的 `preview.log`。

启动器以 20 毫秒的语音能量计算增益并压低瞬时峰值。新版音库含 14 段本机录音，新增的 Ownage 用于没有连杀称号的单次击倒。早期的 13 段音库也可以使用。播报按游戏音效滑块的百分比缩放 PCM 振幅，零音量跳过播放。离线测试截获提交给声音缓冲的实际样本，核对静音、四档中间音量和满音量。

## 离线复核

从源码根目录运行 `scripts/test.ps1 -GameDirectory <游戏目录>`，记下末尾打印的本次测试目录。将下面两处示例路径换成本机路径。32 位 C# 测试会把离屏表面读回文件；Python 重放使用 `pefile` 和 `unicorn` 读取游戏与 HD 模块作为数据。

```powershell
$game = 'D:\Games\RoadRash'
$testDir = 'D:\源码\artifacts\tests\本次测试目录'
& "$testDir\KnockdownTests.exe" $game $testDir
py -3 -B .\tests\knockdown_sprite_replay.py $game $testDir
```

对照早期 GDI 表体时，还需 Pillow、PowerShell 7（.NET 10）和两份历史基线。将本机 `repository/archive/开发记录-截至0.5.0.zip` 中以下命令涉及的两个 EXE 按原相对路径解压到独立目录，再将 `$history` 指向其中的 `repository/artifacts/knockdown`。这些历史基线仅用于离线审计。

```powershell
$history = 'D:\开发归档\repository\artifacts\knockdown'
$prior = "$history/native-sprite/build/RoadRash30thLauncher.exe"
$baseline = "$history/meter-strip/previous-entrypoints/game/RoadRash30thLauncher.exe"
py -3 -B .\tests\knockdown_atlas_audit.py $game "$game/暴力摩托增强启动器.exe" "$testDir/KnockdownTests.exe" "$testDir/atlas" --prior-palette $prior --baseline-launcher $baseline
```

本机取证文件的 SHA-256 为 `ebeb435deb70a2ca20a4a7c0f89aa425eb4d098588967fc1814930bf46e44638`（游戏）和 `f14b3d5447a2b452e6e371b0b01acdd345d6cd9d7d70cf7c155cb3427e139609`（HD）。
